# 目录职责 README 设计

日期：2026-11-20

状态：已确认，进入实现

## 背景

本仓库由多个独立 package、协议契约、服务端、UI 和项目级 Skill 组成。根 README 已介绍 Headless Core 的目标和能力，但没有覆盖每个模块的职责边界，导致目录导航依赖人工阅读源码。

## 目标

- 每个可独立理解的一级目录都有职责说明。
- 每个没有现有 README 的独立 package 都有中文入口说明。
- Headless Core 相关目录能够明确说明依赖方向：UI → Client → Protocol → Server/Core。
- README 内容以“做什么、依赖什么、如何验证”为主，不复制实现细节。
- 不为 `node_modules`、测试夹具、构建产物和隐藏工具目录生成重复文档。

## 文档分层

### 根 README

作为项目总览，包含产品目标、能力矩阵、快速启动、测试方式和目录导航。目录导航只描述一级职责，并链接到模块 README。

### 一级目录 README

覆盖 `apis`、`docs`、`openspec`、`packages`、`patches` 和 `skills`。每个文件说明目录用途、内容分类、维护规则和常用入口。

### Package README

每个 package README 使用统一结构：

1. 目录/包解决的问题。
2. 公开入口或关键子目录。
3. 与其他 package 的边界。
4. 最小验证命令。

已有 README 保留原有技术内容，只在缺少职责或边界时补充；没有 README 的 package 使用中文简明说明。

## 覆盖范围

本次覆盖仓库当前实际存在的目录，不根据截图中但本地不存在的目录创建空壳。新增目录出现时，后续贡献者应在同一目录创建 README，并在根 README 中补充导航。

## 验证

- 检查所有目标目录存在 README。
- 检查 README 中的相对链接目标存在。
- 运行 Prettier Markdown 检查。
- 扫描变更内容，确保没有真实凭据、令牌或本机绝对路径。
- 文档变更不要求运行时回归测试，但保留已有代码测试基线不变。
