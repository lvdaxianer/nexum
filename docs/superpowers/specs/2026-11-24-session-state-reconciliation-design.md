# Session 状态收敛设计

## 目标

修复运行完成后页面同时显示“已完成”和“执行中”的状态分裂：ChatSurface 要收敛同一 run 的时间线项，宿主 Session 列表要实时反映终态。

## 方案

1. 以 `run.settled` 为统一终态边界，按 `runID` 将思考、Agent 输出和模型尝试从进行中状态收敛到 completed/failed/cancelled；已有工具、权限和问题终态不被覆盖。
2. 在 ChatSurface 增加可选 `onSessionStatusChange(sessionID, status)` 回调，终态事件到达时通知宿主。
3. 宿主按稳定 Session ID 浅层更新匹配列表项，保留其他项引用，不重新拉取完整列表。

## 验收标准

- 完成、失败、取消三种结果都不会残留当前 run 的“执行中/输出中”。
- 左侧 Session 列表在事件到达后立即显示对应终态。
- 重复终态事件幂等，现有取消、继续和手动刷新行为不回归。

## 测试策略

- 先添加投影层 RED 测试，再实现最小收敛逻辑。
- 增加宿主状态合并测试。
- 执行受影响包测试、类型检查和根目录完整检查。
