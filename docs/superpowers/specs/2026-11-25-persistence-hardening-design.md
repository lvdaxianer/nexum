# 持久化可靠性加固设计

## 目标

让默认 SQLite Runtime 在重启、并发写入、异常删除和本地文件权限场景下保持可恢复、可诊断且不会因为单次请求读取无限增长的数据。

## 范围

- SQLite 数据目录、数据库文件和 WAL 伴生文件使用私有权限。
- 通过 `PRAGMA user_version` 固化 schema 版本，拒绝未知未来版本。
- SQLite 通用记录读取设置硬上限，避免一次加载无限 payload。
- 将 SQLite Session 及其消息、交互、事件删除收敛为一次数据库事务。
- 不改变内存、JSON 文件适配器的公开行为；它们继续通过现有回调完成删除。

## 事务边界

`NexumSessionService.delete` 仍负责检查 Session 是否存在以及是否正在运行。若持久化组合提供原子删除回调，服务在这些检查之后交给回调完成 Session、消息、交互和事件的删除，避免删除依赖失败后留下半删除状态。没有原子回调时保留现有适配器兼容路径。

## 不在本次范围

- 引入新的加密密钥管理或操作系统 Keychain；SQLite 文件通过权限保护，凭据加密另行设计。
- 为所有 Store 重写分页协议；本轮只阻止 SQLite 通用记录查询无界膨胀。
