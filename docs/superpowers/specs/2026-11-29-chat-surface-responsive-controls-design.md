# ChatSurface 顶部栏开关与窄容器布局设计

## 背景

ChatSurface 需要被其他项目以独立组件方式引入。宿主项目有时不需要组件自带的顶部标题栏；同时，组件被放入较窄容器时，输入栏底部的上传、模式、权限和发送控件会因同一行空间不足而被挤压或裁切。

## 目标

- 保留 ChatSurface 现有默认外观，顶部栏默认显示。
- 允许宿主通过公开参数隐藏顶部标题栏，不影响聊天主体和输入操作。
- 在窄容器中保持所有底部操作可见、可聚焦、可点击，不通过隐藏或横向裁切解决空间问题。
- 保持桌面宽容器的现有单行布局，避免影响已有宿主项目。
- 在 README 中说明参数和窄容器行为。

## 设计

### 顶部栏配置

为 `ChatSurfaceProps` 增加 `showHeader?: boolean`，默认值为 `true`。顶部栏只有在 `showHeader !== false` 且存在 `title` 时渲染。宿主可这样使用：

```tsx
<ChatSurface title="当前会话" showHeader={false} />
```

隐藏只影响 `.nexum-chat-header`，不改变会话初始化、消息区、输入区或底部状态栏。

### 窄容器输入栏

保留所有现有控件，不增加“更多”菜单，也不根据容器宽度隐藏操作。输入栏底部拆分为两个语义区域：

1. 信息行：模型标识和快捷键提示。提示文本允许省略，不能撑破容器。
2. 操作行：上传文件、宿主注入的 `composerExtras`、取消运行确认/按钮、发送按钮。

宽容器下两个区域继续以一行视觉呈现；窄容器下信息行和操作行明确分行，操作行允许继续换行，所有按钮保持自然宽度和最小触控高度。

布局只使用 ChatSurface 根节点已有的 container query，因此组件嵌入侧栏、抽屉或卡片时按实际容器宽度响应，不依赖宿主视口宽度。

### 兼容性与边界

- `showHeader` 不影响 Web Component 的属性协议；同步支持 `show-header="false"` 的布尔属性解析，未传入时保持默认显示。
- 既有 `title` 缺省行为保持不变：没有标题时不渲染顶部栏。
- 窄容器下如果宿主注入的 `composerExtras` 自身包含多个控件，操作行继续换行而不是缩放到不可用。
- 不改动会话、事件流、文件上传和发送请求逻辑。

## 验证

- 增加 `showHeader` 的组件契约测试，覆盖默认显示、显式隐藏和缺省标题。
- 增加 Web Component 属性契约测试，覆盖 `show-header="false"`。
- 增加样式/源码回归检查，确认窄容器下存在信息行和操作行布局规则，且按钮没有被设置为隐藏或横向溢出。
- 运行 `packages/nexum-chat-surface` 的测试和类型检查。
- 使用现有示例或本地测试页面检查宽容器、480px 左右容器和极窄容器下的实际渲染。

## 非目标

- 不把完整工作台打包进 ChatSurface。
- 不新增响应式菜单、按钮优先级或宿主端状态管理。
- 不修改 ChatSurface 的主题、协议适配器和低版本语法构建策略。
