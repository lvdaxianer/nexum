# 计划：修复文件上下文与用户消息回显

## 目标

让模型把上传文件正文当作已经提供的上下文直接使用，同时让用户问题在发送后和历史恢复时始终可见。

## 实施顺序

1. 增加失败测试：Prompt 必须包含明确的本地正文指令；新旧 Prompt 都能解析为用户问题和文件摘要；状态合并不能覆盖已有用户项。
2. 最小实现 Prompt 新边界、Prompt 显示解析器和 pending 状态合并。
3. 更新 ChatItem 回显附件摘要，补充定向浏览器测试。
4. 运行 ChatSurface 测试、Surface 类型检查、构建和根目录检查，完成代码审查、OpenSpec 验证和最终审计。

## 验收标准

- 发送请求仍包含完整文件正文，不调用新的文件 API。
- 模型提示明确禁止按文件名读取工作目录。
- 用户问题和附件名在当前消息及历史消息中可见。
- 初始化、重连、失败恢复不会覆盖已渲染的用户消息。
