# 需求理解子 Skill

从用户业务描述提取指标名称、说明、输入参数、返回字段、筛选、排序、限制、权限和期望状态。

- 默认必须先询问 MySQL 地址、端口、数据库/Schema、只读账号、密码、允许核验的表范围和测试范围；DDL 或业务需求本身不能替代线上元数据证据。
- 只有需求明确写明不需要 MySQL 核验，并明确归档为 `ddl_asserted_consistent` 或 `synthetic_unverified`，才可跳过询问；否则停在门禁处，不能生成 DSL/Python 或调用测试、保存、发布接口。
- 需求、DDL、已有指标视图能推断的内容直接复用，不重复询问。
- 缺少且会影响 DSL、脚本或回填的关键信息必须反问。
- 对明确保证 DDL 与 MySQL 元信息一致的需求标记 `ddl_asserted_consistent`；未明确保证时，必须收集 MySQL 只读连接信息，不能默认按 DDL 生成真实查询。
- 先形成结构化需求摘要，再进入 DDL 映射；不得直接生成 Python。
