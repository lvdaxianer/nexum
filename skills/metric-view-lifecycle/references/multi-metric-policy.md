# 多指标与批量接口策略

## 默认拆分

默认“一种最终输出 Schema 一个 MetricView”。每个指标分别生成、测试、保存和复核；不能把不同结构的多个结果塞入一个 `returnDef`，也不能因为一次 DSL 查询返回多组数据就合并生命周期。

## 允许共享查询

多个指标只有在以下条件全部一致时，才允许在查询层共享一次 DSL：参数集合、时间/业务粒度、表和权限边界、空值语义、状态生命周期和错误处理方式。共享的是只读查询计划，不是 MetricView 对象；最终仍按各自 `returnDef` 映射并分别保存。

## 必须拆分

只要最终字段、粒度、权限范围、状态生命周期、参数形状或业务空值语义不同，就拆成多个视图。一个接口返回多指标时，Skill 应先建立批量清单，逐项记录 `metricViewId`、最终输出字段、测试状态和保存复核状态；任一项阻断不应被其他项的成功覆盖。
