# 操作边界与只读模式

指标视图 Skill 默认是严格只读模式。它可以通过受控的短生命周期只读连接查询 MySQL `information_schema` 做元数据预检，也可以通过已登记接口读取运行时元数据、执行结构化查询、测试候选定义和保存指标视图定义；不能直接连接数据库执行任何写操作。生成的指标视图 Python 仍不得导入数据库驱动。

## 允许的操作

- 读取 DDL/JDBC 元数据、表字段、类型、关系和查询结果；
- 使用只读连接查询 MySQL `information_schema`，核对 DDL 与线上表结构；
- 通过 `/dsl/execute` 或 `/metricView/dsl/execute` 执行只读查询；
- 通过 `/metricView/test`、`/metricView/testExecute` 验证指标视图；
- 通过 `/metricView/save` 保存指标视图定义。该接口是已登记的业务管理接口，不是数据库直连写入；
- 查询无数据时，在 Python 最终返回边界生成至少两条符合 `returnDef` 的、有业务意义且彼此有变化的 Mock 数据；不得用类型默认值凑数。

## 禁止的操作

- 生成或执行 `INSERT`、`UPDATE`、`DELETE`、`MERGE`、`TRUNCATE`、`CREATE`、`ALTER`、`DROP` 等 SQL/DDL；
- 使用 `sqlite3`、`pymysql`、`psycopg2`、`sqlalchemy`、`pyodbc` 等数据库驱动直接连接或写入；
- 为了让测试“有数据”而向真实数据库插入、修改或删除记录；
- 把源表结构 Mock 行当作最终指标返回；
- 把接口异常、鉴权失败、字段错误或类型错误转换成 Mock 成功。

## 业务写操作

如果用户要求新增、修改或删除业务数据，Skill 必须停止数据库操作，要求使用已登记的业务 API。只有接口清单中明确声明的业务接口可以执行副作用，并且必须遵守该接口的确认、授权和审计要求；不能根据表名或 DDL 猜测写接口。

## 无数据处理

真实只读查询成功且 `answer=[]` 时：

1. 保留“真实结构已查询、真实结果为空”的证据；
2. 按最终返回字段、类型、粒度、时间窗口和业务语义生成非空 Mock；
3. 在报告中标明“真实结构验证 + 合成返回数据”；
4. 不修改数据库，也不把 Mock 宣称为真实业务事实。

查询失败、权限失败、参数错误、字段错误或响应结构错误时必须停止或按诊断修复，不能进入 Mock 分支。
