# 测试矩阵

## 模式选择

数据库连接信息默认是必要输入。每次生命周期操作必须先询问；只有用户在当前需求中明确写明不需要 MySQL 核验，并归档为一致性声明或未验证合成测试，才允许跳过：

- 用户提供只读连接信息：先查询并核对 MySQL 元数据，进入真实数据模式，优先查询匹配记录，并在真实测试失败时执行 ReAct。
- 用户明确保证 DDL 与 MySQL 元信息一致：进入一致性声明模式，跳过实时元数据查询，但必须标记未实时核验。
- 用户明确说不需要 MySQL 核验但没有说明属于一致性声明还是合成测试：继续追问模式，不生成候选、不调用 `test`/`save`。
- 用户既未提供连接信息，也未作明确豁免：暂停并反问；不能直接进入合成结构模式。
- 用户明确选择仅做未验证合成测试：进入 `synthetic_unverified`，不证明真实结构或真实业务数据。
- 连接成功但没有匹配记录：保留真实元数据和空结果证据，只在最终返回边界生成符合返回契约的 Mock；不得向数据库写入测试数据。
- 连接失败：记录连接失败原因并暂停；只有用户明确选择未验证合成测试时，才允许另行进入合成模式。

## 真实数据 ReAct 循环

每轮记录 `Plan / Execute / Observe / Repair`：

1. Plan：列出 DSL、路由、参数和预期返回结构。
2. Execute：优先真实只读查询；仅在用户明确选择未验证合成测试时启动合成服务；任何模式都禁止直接写数据库。
3. Observe：核对 HTTP 状态、业务错误、字段类型、空值、重复行、超时和 stdout。
4. Repair：只改动被证据指向的参数/DSL/Python，再从 Plan 开始；最多三轮，超过则向用户报告阻塞。

## 真实模式

用户必须提供只读连接信息和测试范围，除非明确保证 DDL 与 MySQL 元信息一致。凭据不复制到 Skill 目录、不写入参数文件、不进入模型输出、不打印。真实模式先核对元数据，再优先覆盖一条正常数据；如果没有匹配数据，则保留元数据和空结果证据，并按指标视图最终返回定义在最终输出边界生成 schema-compatible mock 记录；DDL/JDBC 与 `typeContext.fields` 只用于校验中间查询和最终字段类型。禁止通过写库、种子 SQL 或源表 Mock 行制造数据。错误参数、鉴权失败、字段错误和传输失败不能用 mock 覆盖。

## 合成模式

只有用户明确选择仅做未验证合成测试时，才用 DDL 中的字段类型和关系配置本地 HTTP stub 的响应，检查本体/非本体/混合路由和统一返回结构。合成模式只证明协议、结构和代码可执行，不证明真实业务数据或线上结构正确，也不允许向真实数据库造数。
