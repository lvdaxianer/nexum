# 指标视图执行模式

指标视图生命周期必须先通过 MySQL 信息门禁，再选择执行模式。默认必须先询问 MySQL 只读连接信息；只有当前需求明确写明不需要 MySQL 核验，且能归档为 `ddl_asserted_consistent` 或 `synthetic_unverified`，才可跳过。不能因为缺少凭据而静默降级。机器决策和阻断字段以 [`blocking-contract.md`](blocking-contract.md) 与 `scripts/execution_mode.py` 为准。

## 模式选择

无论选择真实模式、一致性声明模式还是合成模式，测试入口都必须是接口调用，不得通过浏览器点击页面按钮模拟测试。页面测试只能作为用户人工查看，不是 Skill 的执行通道。

开始前先询问 MySQL 核验信息；如果用户已在当前需求中明确写明不需要核验，再确认其属于哪一种明确豁免模式。

- 用户明确保证：进入 `ddl_asserted_consistent`，可跳过实时元数据查询，但必须在报告中标记未实时核验；
- 用户未明确豁免或表述不确定：必须反问 MySQL 地址、端口、数据库/Schema、只读账号、密码、允许核验的表范围和测试范围；
- 既没有 MySQL 信息也没有明确豁免：流程暂停，不生成 DSL/Python，不调用 `test`/`testExecute`/`save`，不发布；仅当用户明确选择未验证合成测试时才进入 `synthetic_unverified`。

### 真实只读数据模式

仅当用户已经提供，或明确允许通过安全运行时输入以下信息时启用：

- 数据库地址和端口；
- 数据库名、Schema 或 Catalog；
- 只读用户名和密码；
- 允许读取的表范围和测试范围。

真实模式的凭据只能进入短生命周期的只读连接上下文，不能进入模型输出、Skill 文件、生成的 Python、DSL、日志、截图、参数文件或 Git。连接必须设置超时、行数限制和查询范围。严格禁止通过数据库连接执行任何写 SQL、DDL 或造数操作。

真实模式执行以下步骤：

1. 通过短生命周期只读连接读取 `information_schema` 元数据，确认表、字段、类型、关系和允许的表范围；以 MySQL 元数据为准对账 DDL。
2. 优先查找满足业务条件的真实记录；业务字段的具体值不要求与示例完全一致。
3. 以真实记录验证字段结构、字段类型、过滤绑定、空值、重复行和返回契约。
4. 发生接口或 DSL 错误时执行 `Plan → Execute → Observe → Repair`，最多三轮。
5. 记录路由、参数类型、响应摘要和修复依据，不记录凭据或完整数据。

真实模式的 `Execute` 调用 `POST /metricView/test`；候选 Python 在运行时调用对应 DSL 接口。`Observe` 必须消费结构化 `errorCode`、`details` 和 `traceId`。接口返回业务失败不应被当成未处理异常，而应成为下一轮 Repair 的输入。

### 合成结构模式

只有用户明确选择“仅做未验证的合成测试”时进入合成结构模式。用户未提供数据库信息、未保证 DDL 一致、或真实连接不可用时，不能自动进入合成模式，也不能反复以合成结果代替真实元数据核验。

合成模式使用 DDL、字段类型、关系定义和业务返回契约验证代码和最终返回结构；不得向真实数据库写入任何数据。必要的 HTTP stub 只存在于本地测试进程，不代表真实业务数据。

合成模式至少覆盖：

- 一条正常匹配记录；
- 空结果；
- 时间、数值、枚举和 NULL 边界；
- 多表关联后的返回结构；
- 业务要求的部分结果或聚合结果。

合成模式不执行真实数据库 ReAct 循环，只执行一次本地 Coding Gate 和合成服务验证。若本地校验失败，可以修复后重新运行本地校验，但不能伪造真实接口或真实数据通过。报告必须标记 `synthetic_unverified`。

合成服务也必须通过 HTTP 接口模拟 `POST /metricView/test` 和 DSL 执行响应，验证 Skill 能够处理“接口失败 → 读取诊断 → 修复候选 → 再次接口测试”的闭环。

显式合成模式只允许本地合成验证，不允许调用真实 `test/testExecute`，也不自动 `save` 或发布。用户不提供凭据但没有显式选择该模式时，状态必须是 `blocked`。

### 真实只读库无匹配记录

真实只读查询成功但没有满足业务条件的记录时，保留真实元数据和空结果证据，并根据指标视图最终返回定义在 Python 最终输出边界生成 Mock 返回，验证返回协议。不得生成源表 Mock 行后再伪装成真实查询，也不得修改数据库。最终报告必须拆分说明：

- 数据库结构验证：真实；
- 业务样例数据：未从真实库取得，最终返回为合成 Mock；
- 返回结构和类型验证：真实接口或合成接口分别标注。

## 统一成功标准

无论真实模式、一致性声明模式还是合成模式，必须保证：

- DSL 的表、字段、关系和参数绑定结构正确；
- DDL/JDBC 类型、DSL `logicalType` 和 MetricView 参数类型兼容；
- 返回字段名、字段类型、空值、聚合和数组结构符合需求；
- Python stdout 只有协议要求的 JSON；
- Coding Gate 通过后才允许调用测试接口；
- 测试成功后才允许保存，保存后必须 `queryById` 复核。

数据内容只需满足结构和类型契约，不要求与生产样例逐值相同。
