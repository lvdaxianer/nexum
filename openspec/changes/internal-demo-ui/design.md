# Design

## Context

当前页面已经通过 `@opencode/client` 读取模型、Session、SSE 事件、Permission、Question、Skill 和上下文状态。页面代码集中在 `packages/headless-ui/src/main.tsx` 与 `styles.css`，暂无路由和额外 UI 组件层；本次设计保持这一技术边界，不把展示逻辑下沉到 Core。

## Goals / Non-Goals

**Goals:**

- 用企业级工作台布局替换 Hero 主导的概念页布局。
- 让演示者在一个页面内完成“配置模型 → 创建 Session → 发起 Prompt → 处理介入 → 查看结果”的主路径。
- 通过统一的状态映射展示连接、Session、事件、权限、Question、Skill 和上下文压缩状态。
- 复用现有 API Client 和事件流，保持页面可替换。
- 为桌面宽屏和窄屏提供稳定布局，并保持键盘可操作。

**Non-Goals:**

- 不新增 Headless API 路由或修改 Core 行为。
- 不建设完整的多页面管理后台、用户登录、持久化偏好或生产级权限体系。
- 不引入新的 UI 组件库或状态管理依赖。
- 不把当前参考页面升级为不可替换的产品壳层。

## Decisions

### 1. 使用三段式工作台，而不是保留大 Hero

左侧负责项目、Session 和配置，中间负责对话与事件时间线，右侧负责运行状态和待处理介入。这样首屏直接对应演示任务，减少装饰性空间。

备选方案是保留 Hero 并把状态区放在下方；它保留品牌表达，但会把真正的运行状态推到首屏以下，因此不采用。

### 2. 以中文文案和语义状态为默认

页面标题、按钮、帮助文案和错误提示使用中文；事件类型、API 字段、模型名和协议术语保留原始标识。状态同时显示文本与颜色/图标，避免颜色成为唯一信息来源。

### 3. 保持单页状态编排，按区域拆分视图组件

先在现有 Solid 页面中拆出导航、运行头部、Session 工作区、事件时间线、能力状态和介入队列等局部组件。状态仍由页面控制，子组件只接收稳定 ID、状态值和最小事件回调，避免传递大对象图。

### 4. 统一异步操作生命周期

所有保存、探测、创建、发送、回复、决策和重连动作都复用 busy/disabled/成功/失败反馈模式。操作失败不清空输入；事件流异常保留时间线并提供重连。

### 5. 保留现有 API 接入和测试入口

不新增后端接口，继续使用 `@opencode/client` 的 Headless API。已有 Playwright smoke 测试扩展断言中文主路径、能力状态和关键交互；构建、类型检查和 smoke test 作为交付门禁。

## Risks / Trade-offs

- [信息密度过高] → 使用三栏分区、状态标签和折叠/堆叠布局，优先展示当前 Session 和待处理队列。
- [单文件状态复杂] → 保持接口逻辑不变，按 UI 区域拆分纯展示组件；不在本次引入全局状态库。
- [窄屏布局挤压 Prompt] → 在窄屏下按导航、主工作区、状态区顺序堆叠，并让 Prompt 区保持最后可见。
- [演示环境 API 未启动] → 提供明确的离线/未连接空状态，不把空白页面误认为加载失败。

## Migration Plan

1. 在 `packages/headless-ui` 内替换页面结构和样式。
2. 保留现有 API 逻辑与端到端测试夹具，补充视觉和状态断言。
3. 通过类型检查、构建、smoke test 和浏览器预览后合并到 `dev-v0.0.1`。
4. 如需回滚，恢复该包的单次提交即可，不涉及服务端数据迁移。

## Open Questions

无。品牌色、Logo 和生产环境导航可以在后续独立迭代，不影响本次内部演示工作台的规格和实现路径。
