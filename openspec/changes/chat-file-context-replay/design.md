# 设计：修复文件上下文与用户消息回显

## 决策

继续使用浏览器 `File.text()` 读取文件正文，并把正文作为用户消息的一部分持久化。文件路径不参与协议，也不尝试在下次会话中重新访问用户本地文件。

## Prompt 边界

文件正文使用明确的中文边界和说明：正文已经由浏览器读取并随消息发送，模型必须直接基于正文回答，不应根据文件名调用 `read`、`ls` 或其他工作目录工具寻找文件。边界同时包含文件名、正文开始和结束标记，便于历史消息解析。

## 回显策略

发送请求仍使用完整 Prompt，确保模型和历史上下文都有文件正文。ChatItem 不直接把完整 Prompt 当作用户气泡，而是从新格式或上一版本格式中解析出用户问题和文件名，用户气泡显示问题和一个附件摘要，避免长文件内容遮挡问题本身。

## 状态合并

`applyState` 只追加当前尚未展示的权限/问题请求，不再用状态快照替换整个 `chatItems` 列表。这样初始化、重连或重试不会删除乐观展示的用户消息、历史消息或流式结果。
