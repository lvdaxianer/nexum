# Design

## 一致性模型

- 英文默认路径和中文镜像必须描述同一套公开能力。
- 两种语言的标题层级、章节顺序、表格行、代码块数量和公开入口保持一致。
- 代码、导入路径、包名、API 路径、参数名、事件名和协议字段不翻译；只翻译面向读者的说明文字和示例中的自然语言。

## 文档分层

- 根 README 负责定位、安装入口、组合方式和文档导航。
- `docs/README.md` 负责从新手入口进入案例、模块、能力、UI 和架构说明。
- `docs/examples/` 负责按组合方式教学。
- `docs/capabilities/`、`docs/modules/`、`docs/ui/` 和 `docs/architecture/` 负责可查询的能力、模块、交互和分层细节。
- `apis/` 负责完整的 API、Session、事件、请求参数、响应和错误说明。

## 校验策略

- 对每个双语文件对检查标题层级、代码块、公开 API 标识、路由和链接目标。
- 检查英文文档默认存在，中文镜像存在，且两侧语言切换链接互相指向。
- 运行仓库文档验证、链接/结构校验和全量检查；不以“英文文件存在”代替“英文内容完整”。
