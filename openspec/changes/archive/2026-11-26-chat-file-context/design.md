# Design

## Context

当前 `ChatSurface` 在浏览器内维护 Prompt 文本，并通过既有 `ChatProtocolAdapter.sendMessage({ sessionID, text })` 提交；服务端 Prompt 请求仍是 JSON 文本接口，暂无文件存储或上传协议。现有聊天 Surface 已具备发送 busy 状态、错误提示和输入保留模式。

## Goals / Non-Goals

**Goals:**

- 在 ChatSurface composer 内完成单个本地 Markdown/纯文本文件的选择、读取、预览摘要和移除。
- 只在用户发送时把已读取的文本拼接进 Prompt，继续复用既有适配器和服务端接口。
- 对扩展名、大小、读取失败和发送失败提供可恢复的反馈，并防止重复提交。
- 保持 Web Component 和 Solid 组件共享同一行为。

**Non-Goals:**

- 不增加文件上传、文件存储、服务端解析或新 HTTP 路由。
- 不支持二进制文件、目录、拖拽多文件或跨 Session 共享附件。
- 不把本地绝对路径、文件对象或 MIME 类型作为 Prompt 元数据发送。

## Decisions

### 在浏览器端读取文本

使用浏览器 `File.text()` 读取 UTF-8 内容，并仅保留 `{ name, text }` 这类组件状态。相较于新增服务端上传接口，这条路径不改变 Protocol/Client/Server 依赖边界，也能在发送前让用户移除附件；相较于把 `File` 对象直接放入消息状态，文本状态更容易测试、清理和重试。

### 单文件与边界校验

一次只保留一个附件。文件扩展名按文件名最后一段转小写后只接受 `.md` 和 `.txt`，不依赖浏览器提供的 MIME 类型。单文件上限为 512 KiB；该限制在选择阶段校验，给现有约 1 MiB JSON 请求体留出 Prompt 和包装文本空间。大小和类型错误不会清空用户已输入的问题。

### 明确的 Prompt 包装

发送前通过纯函数生成最终文本：先保留用户问题，再附加带文件名的开始/结束分隔标记和全文。这样模型能区分问题与文件上下文，历史消息仍只需保存原有 user text；纯函数单测可以验证换行、文件名和全文不会被遗漏。

### 交互状态与恢复

使用隐藏的 `input[type=file]` 和可见按钮，按钮通过 `accept=".md,.txt,text/markdown,text/plain"` 提示选择器。读取期间阻止发送和重复选择；读取成功显示文件名及移除按钮。发送只在适配器成功返回后清空 Prompt 和附件；读取/发送失败停止 busy 状态、保留输入和附件，并展示下一步操作。

## Risks / Trade-offs

- [文件内容可能包含敏感信息] → 明确提示内容仅在发送时进入 Prompt，组件不额外上传或持久化；由用户主动选择是否发送。
- [512 KiB 不能覆盖超大文档] → 选择阶段给出明确大小限制；超大文件的服务端上传和分段上下文留作独立需求。
- [浏览器文本解码与文件真实编码不一致] → 使用浏览器标准文本读取并在错误时保留附件；不在本次改动中引入编码探测库。
- [拼接后的 Prompt 仍可能触发模型上下文限制] → 只做请求体边界校验，不伪造成功；既有发送失败恢复路径保留原问题和附件。

## Migration Plan

无需数据迁移或服务端发布。前端构建后即可使用；回滚只需移除 ChatSurface 文件选择入口和对应本地状态，不影响已有历史消息或 Protocol 数据。
